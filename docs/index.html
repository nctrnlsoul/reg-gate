How it works

1

Fetch

Every node in the Chainlink DON pulls the same finished window of Federal Register publications from watched regulators: SEC, CFTC, Treasury, OCC, FDIC, Fed, FinCEN, OFAC, CFPB, IRS and the White House.

2

Classify and agree

A deterministic rules engine sorts documents into four categories. Final rules and executive orders mean BLOCK; proposals and notices mean REVIEW. Nodes must agree byte for byte. No LLM in the decision path.

3

Write and enforce

The signed result lands in RegGateStatus. Tokens ask it before each transfer: strict tokens pass only on OK, lenient tokens pass on anything but BLOCK.

4

Re-verify on override

When a reviewer clears a BLOCK, the contract emits LatchCleared. That event triggers the workflow again, so the clear is checked against the freshest Federal Register data within minutes.

Fail-closed by design

  • No report, or a stale one: every category reads BLOCK.
  • API down, bad data, or nodes disagree: nothing is written, so the contract goes stale and blocks.
  • A BLOCK latches: it holds through later OK reports until a human reviewer clears it.
  • Cleared, but the same rule is still in the window: REVIEW, never OK.
  • A reviewer clear triggers a re-check: the workflow listens for the LatchCleared event and re-verifies against the Federal Register at once, so a newer blocking rule re-latches in minutes, not hours.
  • Only Chainlink's forwarder can write, bound to this chain, with a strictly increasing timestamp to stop replays.
  • This page fails closed too: if it cannot reach Sepolia, it shows UNKNOWN, never OK.
